## 전체 흐름도

```
유저 "문제 생성" 클릭
       │
       ▼
┌─────────────────────────────────────────────┐
│ 1단계: 프롬프트 조립                          │
│                                             │
│  기본 출제 지시                               │
│  + 법령 컨텍스트 (law-context.ts)            │
│    └ 2025년 세율표, 공제한도, 회계기준         │
│  + 난이도 캘리브레이션 (difficulty-calibration)│
│    └ 기출 수준 few-shot 예시                  │
│  + 출제 패턴 랜덤 선택 (4가지)                │
│    └ 사례형 / 계산형 / 비교형 / 조건판단형     │
│  + QA 피드백 동적 주입 (qa-feedback.ts)       │
│    └ 과거 이슈가 반복되지 않도록 지시 추가      │
│  + system 메시지로 포맷 강제                   │
│    └ 객관식: "choices 5개 + answer 정수"      │
│    └ 주관식: "answer 문자열"                   │
└──────────────┬──────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────┐
│ 2단계: AI 생성 (Claude Sonnet)               │
│                                             │
│  model: claude-sonnet-4-20250514            │
│  max_tokens: 4096                           │
│  → JSON 응답 파싱                            │
└──────────────┬──────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────┐
│ 3단계: 포맷 검증 (즉시, AI 호출 없음)         │
│                                             │
│  객관식 체크:                                 │
│   ✓ choices 배열 존재하고 정확히 5개인가       │
│   ✓ 각 선택지에 number(정수)와 text(문자열)    │
│   ✓ answer가 1~5 정수인가                    │
│   ✓ body가 30자 이상인가                      │
│   ✓ explanation이 50자 이상인가               │
│                                             │
│  주관식 체크:                                 │
│   ✓ answer가 문자열이고 20자 이상인가          │
│   ✓ body가 30자 이상인가                      │
│   ✓ explanation이 50자 이상인가               │
│                                             │
│  실패 시:                                     │
│   → AI에 오류 내용 피드백 후 재생성 (1회)      │
│   → 그래도 실패 시 재생성 (최대 2회)           │
│   → 3회 모두 실패 시 에러 반환                 │
└──────────────┬──────────────────────────────┘
               │ 포맷 통과
               ▼
┌─────────────────────────────────────────────┐
│ 4단계: 검증 에이전트 (별도 Claude 호출)        │
│                                             │
│  검증 대상:                                   │
│   1. 정답 정확성                              │
│      - "문제를 직접 풀어보고 정답이 맞는지"     │
│      - 객관식: 5개 중 제시된 번호가 맞는지      │
│      - 주관식: 계산 과정 재검산                 │
│                                             │
│   2. 선택지 품질 (객관식)                      │
│      - 정답이 유일하게 맞는지                   │
│      - 다른 선택지도 정답일 가능성은 없는지      │
│                                             │
│   3. 해설 일관성                               │
│      - 해설이 정답과 일치하는지                  │
│      - 해설에서 다른 번호를 정답이라고 하진 않는지│
│                                             │
│   4. 법조문 정확성                             │
│      - 인용된 조문이 실제 존재하는지             │
│      - 조문 내용이 맞는지                       │
│                                             │
│  결과:                                        │
│   ✅ passed=true → 그대로 반환                 │
│   ❌ passed=false + correct_answer 제시        │
│      → 정답 번호 수정 후 반환                   │
│   ❌ passed=false + fixed_explanation 제시      │
│      → 해설 수정 후 반환                        │
└──────────────┬──────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────┐
│ 5단계: 유저에게 반환                           │
│                                             │
│  반환 데이터:                                  │
│   - id: UUID                                │
│   - body: 문제 본문                           │
│   - choices: 선택지 5개 (객관식)               │
│   - answer: 정답 (정수 or 문자열)              │
│   - explanation: 해설                         │
│   - verified: true/false                     │
│   - subject, topic, difficulty, session, type │
└─────────────────────────────────────────────┘
```

## 사후 검증 (유저 신고 시)

```
유저 "오류가 있나요?" 클릭
       │
       ▼
┌─────────────────────────────────────────────┐
│ 인라인 신고 패널                               │
│                                             │
│  유저 선택:                                    │
│   - 오류 유형: 정답오류 / 해설오류 / 법령구버전 │
│   - 설명 (선택)                               │
│                                             │
│  자동 첨부:                                    │
│   - 해당 문제 전체 데이터                       │
│     (body, choices, answer, explanation)      │
└──────────────┬──────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────┐
│ QA 에이전트: 재검증                            │
│                                             │
│  → 검증 에이전트 재호출 (4단계와 동일)          │
│                                             │
│  결과 분기:                                    │
│   ✅ 오류 확인 + 수정 가능                     │
│      → status: "fixed"                       │
│      → 유저에게: "자동 수정됨 + 코인 환불"      │
│      → QA 피드백 등록 (생성팀 프롬프트 반영)    │
│      → 영향 유저 추적 시작                      │
│                                             │
│   ✅ 오류 아님                                 │
│      → status: "not_error"                   │
│      → 유저에게: "정답 확인됨"                  │
│                                             │
│   ⏳ 판단 불가                                 │
│      → status: "pending"                     │
│      → 유저에게: "검토 중, 결과 알림 예정"      │
│      → 관리자 대시보드에 표시                    │
└──────────────┬──────────────────────────────┘
               │ 오류 확인 시
               ▼
┌─────────────────────────────────────────────┐
│ QA→생성팀 피드백 루프                          │
│                                             │
│  1. 이슈 유형 분류:                            │
│     - duplicate_choices (선택지 중복)          │
│     - missing_wrong_explanation (오답해설 누락) │
│     - keyword_mismatch (해설-정답 불일치)      │
│     - calculation_error (계산 오류)            │
│     - outdated_law (법령 구버전)               │
│                                             │
│  2. 프롬프트 수정 지시 자동 생성:               │
│     예) "⚠️ 선택지 중복 금지: 5개 반드시        │
│          서로 다른 내용이어야 합니다"            │
│                                             │
│  3. 같은 유형 누적 시 심각도 상승:              │
│     1~2건 → low                              │
│     3~4건 → medium                           │
│     5건+  → high                             │
│                                             │
│  4. 다음 문제 생성 시 자동 반영:                │
│     프롬프트 끝에 "## 품질 개선 지시" 삽입      │
│     → 같은 실수 반복 방지                       │
└─────────────────────────────────────────────┘
```

## 검증 포인트 요약

| 단계 | 검증 내용 | 방법 | 실패 시 |
|------|----------|------|--------|
| 3단계 포맷 | 선택지 5개, 정답 정수, 길이 | 코드 즉시 체크 | 재생성 (최대 2회) |
| 4단계 정답 | 정답 정확성, 계산 재검산 | 별도 Claude 호출 | 정답 수정 반영 |
| 4단계 해설 | 해설-정답 일치, 법조문 존재 | 별도 Claude 호출 | 해설 수정 반영 |
| 사후 신고 | 유저가 발견한 오류 | QA 에이전트 재검증 | 수정 + 피드백 등록 |
| 피드백 루프 | 반복 이슈 프롬프트 반영 | 동적 주입 | 자동 개선 |
